# RimTalk用 日本語Scribanテンプレート

[RimTalk](https://github.com/jlibrary/RimTalk)の会話を、ポーンの性格・人間関係・現在の状況に合わせやすくする日本語テンプレートです。

「戦闘中なのにのんびり話す」「毎回気温の話になる」「遺体を運んでいるのに生きた人物として話す」といった、AIに状況が伝わりにくい場面を補います。ゲーム内の情報を選び、整理して、AIへ送る指示文にまとめます。

Scriban対応のRimTalkで、会話を生成できる環境を用意してから導入してください。文章を生成するのは設定したAIモデルのため、会話の自然さや指示への従いやすさはモデルによって変わります。

## できること

### 性格や立場に合った会話にする

独り言・二人の会話・複数人の会話で指示を切り替えます。入植者、訪問者、囚人、奴隷、敵対勢力などの立場を伝え、プレイヤー側の人物と敵が話す場面では、対立した会話を促します。

プレイヤー派閥は実際の派閥名で表記します。配偶者・家族などの関係は、会話相手や作業対象に関係する人物を「人物関係」欄へ抜き出します。12歳以下のポーンには、年齢相応の言葉遣いや感情反応を反映するよう追加で指示します。

### 脅威の規模に合った会話にする

攻撃行動や目前の近接脅威、徴兵とマップの危険度から交戦を判定し、戦闘中は冒頭の指示を切り替えます。マップ上で活動中の敵についても、派閥と規模を伝えます。

敵性生物だけが脅威となっている場合は、次の段階で表現を調整します。捕食種でも個体数のしきい値は共通です。

| 個体数 | 非捕食種 | 捕食種 |
| --- | --- | --- |
| 1～9体 | 少数の敵性生物 | 少数の捕食生物 |
| 10～29体 | 敵性生物の群れ | 捕食生物の群れ |
| 30体以上 | 敵性生物の大群 | 捕食生物の大群 |

混在している場合は「捕食生物を含む～」と補足します。ゲーム内部で生物として扱われるMOD種族も考慮し、この脅威説明には「動物」という表現を使っていません。

周辺状況は、プレイヤー入植者だけの会話・独り言に表示します。トレーダーが滞在している場合は、武器商などの種別も伝えます。

### 武器や作業対象の取り違えを減らす

危険な状況や狩猟中には、装備中の武器をSystem・User両方に記載します。表示対象の状況で武器情報がなければ「武器なし」と示し、衣服の一覧は省きます。

運搬・解体などの対象が遺体なら、元のポーンの名前・種別・所属を補足します。

```text
【作業内容】
ポーチを運搬中
作業対象の補足：ポーチという人間の遺体（プレイヤー陣営に敵対／所属派閥「モイクポ」）
```

これはAIへ渡す情報の例です。人間・動物・メカノイド・異常存在を区別し、MODの人型種族は種族の表示名を使います。味方の遺体、囚人、奴隷なども区別し、同じ遺体の補足は重複させません。

### 怪我や喧嘩の状況を会話へ反映する

健康情報は、原則としてゲーム内時間で40時間以内に付いた状態を表示します。部位のある怪我に加え、「全身」に付く病気・効果なども対象です。ゲーム開始時以前からの状態は時間判定で除外します。

RimTalkから出血の重症度や死亡予測を取得できる場合は、それも残します。失血死の予測があるときはSystem側にも生命の危機を伝えます。

喧嘩中は小さな口論として、終了直後は怒りや気まずさが残る会話として扱います。さらに、表示対象の健康情報と直近40時間以内の喧嘩メモリが両方ある場合は、怪我の一部が相手との口論によるものだという一文を加えます。この補足はメモリに基づくもので、個々の傷の原因を厳密に特定するものではありません。

### 天気や気温に話題が偏りすぎないようにする

場所を「室内・屋外」「部屋」「必要な温度」「天候・外部環境」に整理します。

- 温度は35℃以上、または－10℃以下のときに表示します。
- 天候情報から「軌道上」と判別できる場合は、温度を省きます。
- 快晴・霧・雨・霧雨・小雪は、初期設定では10%の確率で表示します。
- 太陽フレアなどのマップイベントも補います。性別が記載されたイベントは、対象性別のポーンにだけ表示します。
- 熱帯雨林・温帯森林などのバイオームは、初期設定では10%の確率でSystemへ表示します。

確率は変更できます。天候・マップイベントは、辞書に登録されていないものは原則表示します。

### 話題にしたい情報を選ぶ

特性は、辞書に登録したものだけを表示します。欲求・思考も、登録した項目を指定の確率で表示できます。

派閥名や作業内容の表記を変更したり、AIが知らないMODの敵に説明を付けたりできます。例えば「パイクマン」に武装の説明を登録すると、作業内容では名前に説明を添え、健康情報では傷の一覧とは別に一度だけ攻撃元の説明を補います。

通常の会話では、RimTalkの履歴に含まれる過去のAI出力を参考情報として使います。

### 特定のきっかけで、専用シーンへ切り替える

UN（ユニークシーン）は、交流履歴や現在の作業に指定キーワードがあったとき、該当する一人のシーン描写へ切り替える機能です。

例えば「キャッチボール」という記録をきっかけに、その場面を描写する専用の指示を送れます。対象の性別・最低年齢・発火率・指示文を変更でき、不要なら無効にできます。

UNが発火すると、会話参加者が複数いても最初に条件を満たした一人だけを扱い、User側は名前・年齢・性別・性格に絞ります。通常の過去会話履歴は追加しません。参加者が戦闘中、または一人でも徴兵中の場合は発火しません。

## 導入方法

このREADMEは、設定名が`UN_keyword`になっている更新版を対象としています。冒頭に`NS_keyword`がある旧版とは設定名や機能が異なります。System・Userは同じ版の組み合わせで使用してください。

1. RimTalkで使用するAIモデルを設定し、通常の会話が生成できることを確認します。
2. プロンプト設定で新しいプリセットを作成します。
3. プリセット内の`JSON Format`・`Chat History`・`Dialogue Prompt`をオフにします。出力形式と履歴は、このテンプレート側で組み立てます。
4. 次の2つの項目を、それぞれ配布ファイルの全文で置き換えます。

   | プリセットの項目 | 貼り付けるファイル | ロール |
   | --- | --- | --- |
   | Base Instruction | [Base Instruction.txt](https://github.com/gabyounosabi/Scriban_ja/blob/main/Base%20Instruction.txt) | System |
   | Pawn Profiles | [Pawn Profiles.txt](https://github.com/gabyounosabi/Scriban_ja/blob/main/Pawn%20Profiles.txt) | User |

5. コンテキスト最適化を無効、最大ポーン数を3、会話セッションを1、ポーン情報をすべてONにします。
6. プリセットを有効にし、生成されるプロンプトを確認します。

RimTalkのバージョンや翻訳によって設定画面の表記が異なる場合があります。設定画面の基本操作は[RimTalkの説明](https://github.com/jlibrary/RimTalk#4-configuration)も参照してください。

編集は、別のテキストエディタへ全文をコピーしてから行うことをおすすめします。コードの一部だけでなく、先頭の`{{~`から末尾まで貼り付けてください。

## カスタマイズ

まずはテンプレート冒頭の設定と辞書を編集してください。辞書の左側が「探す文字列」、右側が「表示する文字列」または「表示確率」です。辞書によって一致のしかたや空文字の意味が異なります。

### よく使う設定

| 変更したいこと | 設定名 | 編集する側 |
| --- | --- | --- |
| 表示する特性を選ぶ | `trait_display_dict` | User |
| 不要な健康情報を除外・短縮する | `replace_dict` | User |
| 作業内容の文字列を除去・置換する | `job_replace_dict` | User |
| 作業対象・怪我の攻撃元へ説明を付ける | `pawn_description_dict` | User |
| 派閥の表示名を変える | `faction_display_dict` | System・Userの両方 |
| トレーダー種別の表示名を変える | `trader_kind_replace_dict` | System |
| 欲求・思考の表示確率を変える | `thought_display_dict` | User |
| 天候の表示確率を変える | `weather_display_chance_dict` | User |
| マップイベントの表示確率を変える | `map_event_display_chance_dict` | User |
| バイオームの表示確率を変える | `biome_display_chance` | System |

<details>
<summary>辞書の書き方と、空文字の扱い</summary>

以下は、既存の同名辞書を編集する例です。新しいテンプレートとして追加するものではありません。

```scriban
trait_display_dict = {
  "地底人": "地底人",
  "よたか": "夜間の活動を好む",
}
```

特性名に部分一致したものを表示します。未登録の特性と、右側が`""`の特性は表示しません。

```scriban
faction_display_dict = {
  "闇の存在": "異形",
}
```

派閥名への完全一致で、AIへ見せる名前を変更します。ゲーム内の派閥名は変わりません。遺体の所属派閥にも適用されます。System・Userの両方を同じ内容にしてください。

健康情報の`replace_dict`は、右側が空かどうかで動作が変わります。既存辞書の「ここから下は自由」以降に、次のような項目を追加・編集できます。

```scriban
"再生 (": "",
"制御不能な触手": "触手",
```

前者は「再生 (」を含む健康項目全体を除外します。後者は一致部分だけを短縮するので、`制御不能な触手 (アクティブ)`は`触手 (アクティブ)`になります。既存の同じキーは書き換え、重複登録しないでください。

`job_replace_dict`と`trader_kind_replace_dict`は一致部分だけを置換します。右側を`""`にすると、その部分だけを除去します。`pawn_description_dict`は作業内容では部分置換、健康情報では表示対象の傷に含まれる攻撃元の説明をキーごとに一度だけ別記します。

確率は0～100で指定します。0は非表示、100は常時表示です。欲求・思考は部分一致で登録したものだけを表示し、天候・マップイベントは完全一致した名前に確率を適用します。マップイベントは、性別・強度まで含む表示名が未登録なら本体の名前でも辞書を確認します。

`replace_dict`前半の性別やラベルを整える項目は残してください。部分一致・部分置換では辞書の順番も結果に影響するため、似たキーは具体的で長いものを先に置きます。

</details>

<details>
<summary>性格・ペルソナを状況に応じて切り替える</summary>

ポーンのペルソナ欄では、通常の文章に加えて次の記法を使えます。

```text
落ち着いた口調で話す
{30%}趣味の料理のことを時々思い出す{END}
{"マッファロー"}マッファローの世話が好き{END}
{!}危険な状況では口数が減る{END}
{UN}その場で感じたことを丁寧に言葉にする{END}
```

| 書き方 | その行を使う条件 |
| --- | --- |
| 普通の文章 | 常に使用 |
| `{30%}本文{END}` | 指定した確率で使用 |
| `{"キーワード"}本文{END}` | 表示用に整えた人物情報などにキーワードがあるとき |
| `{!}本文{END}` | マップの危険度がLow・Highのとき |
| `{UN}本文{END}` | UNが発火し、シーン文を取得できたとき |

`{!}`はマップの危険度による判定なので、本人が直接戦っている場合だけに限定されません。キーワード判定には、UN発火時だけ取得・置換済みのシーン文も加わります。

特殊記法は1行につき1個にし、本文には追加の`}`を入れないでください。入れ子には対応していません。通常の設定文でも、波括弧は特殊記法として扱われることがあります。

</details>

<details>
<summary>UN（ユニークシーン）を設定する</summary>

System・Userの両方で、以下の設定を揃えてください。

```scriban
UN_gender = "ALL"
UN_chance = 50
UN_keyword = {
  "キャッチボール": "",
  "球技をして遊んだ": "ボールで遊んでいた",
}
```

この例では性別を問わず、条件を満たした場面の発火率を50%に設定します。配布コードの初期値は女性・50%です。無効にする場合は両方の`UN_chance`を0にします。

`UN_gender`には`"Male"`・`"Female"`・`"ALL"`を指定できます。最低年齢は少し下にある`UN_min_age`で変更し、こちらも両方を揃えます。初期値は20歳以上です。

交流履歴（`fullinteraction`）を行順に部分一致検索し、一致がなければ現在の作業（`p.job`）を検索します。作業内容は辞書で置換する前の原文が対象です。

右側が`""`なら一致した行をそのまま使います。文章を設定した場合は、その行全体を設定した文章へ置き換えます。過去のAI生成文が交流履歴に含まれることもあり、同じ記録から再び発火する場合があります。発火回数や「一度使った記録」の管理は行いません。

専用の指示文は、System側の`UN_instruction`で変更します。

```scriban
UN_instruction = "あなたはロールプレイAIです。{name}の以下のシーンを描写してください\n"
```

`{name}`は対象ポーンの名前に置き換わります。SystemとUserの切り替えを揃えるため、UNの確率判定はゲーム内時刻と履歴の長さに基づきます。同じ状態でプレビューを繰り返しても、独立した抽選にはなりません。

</details>

## 利用上の補足

- マップの敵情報はマップ全体の集計です。目の前の交戦相手だけを数える機能ではなく、未探索・不可視の敵を完全に除外できるわけでもありません。
- 種族固有の健康状態など、途中で生成されたポーンに最初から付く効果は、後天的な状態と区別できない場合があります。不要なものは辞書で除外できます。
- 遺体の敵味方判定は、残っている所属情報と現在の外交関係に基づきます。死亡時点の関係を記録する機能ではありません。
- RimTalkの情報設定やMODによって、取得できる項目・名称が変わります。情報が空の場合、表示されない項目や「武器なし」になる場合があります。
- 編集後はプレビューで、コードそのものやエラーがプロンプトに出ていないか確認してください。構文エラー時は、RimTalkからテンプレート本文がそのまま返される場合があります。

表示がおかしい場合は、使用しているRimWorld・RimTalkのバージョンと、生成されたSystem・Userプロンプトを添えると状況を確認しやすくなります。
